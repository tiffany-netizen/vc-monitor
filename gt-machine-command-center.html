Current Gaps

No unified data layer

Supabase has some data, Gobii has some, RecruiterFlow has some. No single place to see everything. Bolt UI only sees Supabase.

Manual messaging workflow

Supabase Table Structure (Recommended)

people
id, name, email, title, company_id, tier (1/2/3/VC/OG), source (RF/Apollo/OG), enriched (bool), email_found (bool), status (queued/active/archived), linkedin_url, last_job_change, warm_intro_path, created_at, updated_at
companies
id, name, website, jobs_url, tier (1/2/3/Machine/VC), vc_investor, funding_stage, funding_amount, last_funding_date, dna_fit (bool), portfolio_of (vc name), headcount, industry, status (active/archived), last_scraped, created_at
jobs
id, company_id, title, url, source (scrape/vc_portco/og_forum), dna_fit (bool), first_seen, last_seen, status (new/active/closed), warm_contact_id (FK to people), vc_source, notified (bool)
drafts
id, person_id, company_id, job_id, type (outreach/follow_up/og_intro), subject, body, status (draft/reviewed/sent/skipped), sent_at, created_at
vc_firms
id, name, contact_name, contact_email, portfolio_url, last_scraped, created_at
activity_log
id, type (enrichment/scrape/draft/send/archive/alert), scenario_id, person_id, company_id, details (json), created_at

Step-by-Step: Priority 1 - Supabase Tables

1
Open Supabase Dashboard, go to SQL Editor
Navigate to your project. Click "SQL Editor" in the left sidebar.
Tool: Supabase
2
Create the "people" table
Run CREATE TABLE with columns: id (uuid, primary key, default gen_random_uuid()), name (text), email (text), title (text), company_id (uuid, nullable), tier (text, check in 'Tier 1','Tier 2','Tier 3','VC','OG'), source (text), enriched (boolean default false), email_found (boolean default false), status (text default 'queued'), linkedin_url (text), last_job_change (timestamptz), warm_intro_path (text), rf_id (text for RecruiterFlow ID), created_at (timestamptz default now()), updated_at (timestamptz default now()).
Tool: Supabase SQL Editor
3
Create the "companies" table
Columns: id (uuid PK), name (text), website (text), jobs_url (text), tier (text), vc_investor (text), funding_stage (text), funding_amount (text), last_funding_date (date), dna_fit (boolean), portfolio_of (text), headcount (int), industry (text), status (text default 'active'), last_scraped (timestamptz), created_at (timestamptz default now()).
Tool: Supabase SQL Editor
4
Create "jobs", "drafts", "vc_firms", and "activity_log" tables
Follow the schema from the Architecture tab. Add foreign keys: jobs.company_id references companies.id, drafts.person_id references people.id, etc.
Tool: Supabase SQL Editor
5
Enable Row Level Security and create API keys
In Supabase, go to Authentication > Policies. For your Bolt UI, use the anon key with RLS policies that allow read/write. For Make.com, use the service_role key (keep it secret).
Tool: Supabase Dashboard
6
Seed VC firms data
Insert your 35+ VC firms (Greycroft, Point72, Canvas, etc.) into the vc_firms table with their portfolio URLs and contact info.
Tool: Supabase SQL Editor

Step-by-Step: Priority 2 - RecruiterFlow to Supabase

1
Create a new Make.com Scenario
Name it "RF Contact Ingest". Set schedule to every 15 minutes (or whatever polling frequency you want).
Tool: Make.com
2
Add HTTP module: GET RecruiterFlow contacts
Use RecruiterFlow API (https://api.recruiterflow.com/v1/contacts). Filter by updated_since parameter using the last run timestamp. Add your RF API key in the header.
Tool: Make.com HTTP module
3
Add Filter: Only contacts tagged Tier 1, Tier 2, Tier 3, VC, or OG
After the HTTP call, add a Filter module. Check if the contact's tags array contains any of your target tags.
Tool: Make.com Filter
4
Add Supabase module: Upsert into "people"
Use Make.com's Supabase integration (or HTTP module with Supabase REST API). Map RF fields to your people table columns. Use rf_id as the conflict key so duplicates update instead of creating new rows.
Tool: Make.com + Supabase

Step-by-Step: Priority 7 - Claude API for Message Drafting

1
Get an Anthropic API key
Go to console.anthropic.com, create an API key. Store it as a Make.com connection or variable.
Tool: Anthropic Console
2
Add HTTP module in your Make.com enrichment flow
After Apollo enrichment and job scraping, add an HTTP POST to https://api.anthropic.com/v1/messages. Headers: x-api-key, anthropic-version, content-type.
Tool: Make.com HTTP module
3
Build the prompt template
In the HTTP body, pass a system prompt with Jamie's voice/style examples and the outreach templates from your doc (like the OG intro email). Pass the person's data, company info, and relevant jobs as the user message. Ask Claude to draft the email.
Tool: Make.com HTTP module body
4
Parse response and save to Supabase drafts table
Extract the message content from Claude's response. Insert into Supabase drafts table with person_id, company_id, job_id, subject, body, status='draft'.
Tool: Make.com + Supabase
5
Add Gmail draft creation module
After saving to Supabase, add a Gmail module that creates a draft (not sends) with the generated subject and body. To field = the person's email. This way you review in Gmail before hitting send.
Tool: Make.com + Gmail

Step-by-Step: Priority 4 - Python Scraper to Supabase

1
Install supabase-py in your Python environment
Run: pip install supabase. Import it in your scraper script.
Tool: Python
2
Add Supabase connection to your scraper
At the top of your script: from supabase import create_client. Use your project URL and service_role key. Initialize: supabase = create_client(url, key).
Tool: Python
3
Replace HTML output with Supabase upsert
Where your script currently writes to the HTML file, instead call: supabase.table('jobs').upsert({'company_id': company_id, 'title': job_title, 'url': job_url, 'source': 'vc_portco', 'vc_source': vc_name, ...}).execute(). Use the job URL as the unique key to avoid duplicates.
Tool: Python + Supabase
4
Keep HTML output as backup (optional)
You can keep the HTML generation as a secondary output while Supabase becomes the primary destination. Just run both.
Tool: Python

Step-by-Step: Priority 9 - Slack Notifications

1
Create a Slack channel for alerts
Something like #gt-machine-alerts. Add Tiffany and Jamie.
Tool: Slack
2
Create Slack incoming webhook
Go to api.slack.com/apps, create an app (or use existing), add Incoming Webhooks, select your channel. Copy the webhook URL.
Tool: Slack API
3
Add Slack notification step to Make.com scenarios
In your job monitoring and enrichment Make.com scenarios, add a final HTTP POST to the Slack webhook URL. Format the message with the company name, job title, warm intro path, and a link to the Bolt UI or job posting.
Tool: Make.com + Slack

Step-by-Step: Priority 12 - Job Change Detection

1
Create Make.com scheduled scenario: "Weekly Job Change Check"
Set to run weekly (Sundays or Mondays). This polls Apollo for updated employment data on your tracked contacts.
Tool: Make.com
2
Pull active people from Supabase
First module: HTTP GET from Supabase REST API. Filter: status = 'active' AND tier IN ('Tier 1','Tier 2','Tier 3','OG'). This gives you the list of people to check.
Tool: Make.com + Supabase
3
For each person, call Apollo People Enrichment
Use Apollo's /v1/people/match endpoint with email or LinkedIn URL. Compare the returned title and company to what's stored in Supabase. If different, that's a job change.
Tool: Make.com + Apollo API
4
On change detected: update Supabase, check DNA fit, route accordingly
Update person's title and company_id in Supabase. Check if new company fits DNA (VC-backed, right size, right industry). If yes: keep active, trigger Scenario 2 workflow. If no: set status to 'archived'. Either way, log to activity_log and fire Slack notification.
Tool: Make.com + Supabase + Slack
